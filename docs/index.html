UltraGame — motor 2D y 3D para la web

Un único archivo JavaScript sin dependencias con lo que usan los juegos 2D de verdad: renderizado por WebGPU, WebGL2, WebGL y Canvas 2D con respaldo automático, escenas al estilo Phaser, grafo de escena al estilo PixiJS, física Arcade, mapas de Tiled, audio con sintetizador, partículas aceleradas con WebAssembly SIMD, 35 efectos de post-proceso, interfaz táctil y herramientas de seguridad para juegos web3. Incluye 3D (PBR, sombras, glTF/GLB de Blender, animación por huesos, física de personajes y vehículos) y UltraGame Studio, un editor de escritorio para crear juegos 2D y 3D con o sin código.

Lo mejor de PixiJS

Grafo de escena con contenedores, máscaras, filtros por objeto, cacheAsTexture, mallas, cuerdas, texto con estilos, lotes instanciados y alfa premultiplicado.

Lo mejor de Phaser

Escenas con preload/create/update, this.add.*, física Arcade con grupos y colisionadores, tweens encadenables, cámaras con efectos, Tiled y audio.

Lo propio

Cuatro backends verificados píxel a píxel, núcleo WASM SIMD opcional, sintetizador de efectos y música, grabador GIF, RNG determinista, hash de estado y API de seguridad.

Inicio rápido

Copia dist/ultragame.js en tu proyecto (o usa dist/ultragame.esm.js con import) y crea un juego con una escena. El motor expone el espacio de nombres global UG (alias UltraGame).

<div id="juego"></div>
<script src="ultragame.js"></script>
<script>
const Principal = {
  key: 'Principal',
  preload() {
    this.load.image('estrella', 'img/estrella.png');   // o genera texturas por código:
    this.textures.generate('bola', 32, 32, (c) => { c.fillStyle = '#ffd43b'; c.beginPath(); c.arc(16, 16, 15, 0, Math.PI * 2); c.fill(); });
  },
  create() {
    this.jugador = this.physics.add.sprite(400, 300, 'bola');
    this.jugador.body.setCollideWorldBounds(true).setBounce(0.6);
    this.teclas = this.input.keyboard.createCursorKeys();
    this.add.text(20, 20, '¡Hola, UltraGame!', { fontSize: 28, fill: 0xffffff, stroke: 0x000000, strokeThickness: 4 });
    this.tweens.add({ targets: this.jugador, scale: 1.3, duration: 600, yoyo: true, repeat: -1, ease: 'sineInOut' });
  },
  update(tiempo, delta) {
    const b = this.jugador.body, v = 260;
    b.setVelocityX(this.teclas.left.isDown ? -v : this.teclas.right.isDown ? v : 0);
    if (this.teclas.up.isDown && b.onFloor()) b.setVelocityY(-520);
  }
};

new UG.Game({
  parent: 'juego', width: 800, height: 600, backgroundColor: 0x1b1035,
  physics: { arcade: { gravity: { y: 1200 } } },
  scenes: [Principal]
});
</script>
Con módulos: import UG from './ultragame.esm.js'. En Node (pruebas, servidores de validación) require('./dist/ultragame.js') carga toda la lógica que no necesita navegador: matemáticas, física, Tiled, tweens, RNG, seguridad y GIF.

Renderizadores

Los cuatro backends comparten la misma API y producen la misma imagen (la batería de pruebas compara píxeles en cada uno). El orden por defecto es UG.defaultRendererOrder = ['webgl2', 'webgpu', 'webgl', 'canvas']: WebGL2 es hoy el más estable en todos los navegadores; pide renderer: 'webgpu' para priorizar WebGPU.

BackendTécnicaNotas
WebGPUComandos diferidos, 3–4 writeBuffer por frame, uniformes con offsets dinámicos, quads instanciados.Shaders WGSL. Textos y canvas dinámicos se suben por CPU (writeTexture) para evitar sincronizaciones.
WebGL2VAO, anillo de 3 búferes, instancing, multi-textura por lote.Recuperación automática tras pérdida de contexto.
WebGL 1GLSL ES 1.00, ANGLE_instanced_arrays si existe; si no, quads indexados.Máxima compatibilidad (móviles antiguos).
Canvas 2DTransformaciones afines, caché de tintes (LRU), máscaras por composición, mallas por triángulo.Los filtros usan su equivalente CSS (ctx.filter) cuando existe; cacheAsTexture guarda un canvas persistente.

Todos usan alfa premultiplicado y los modos de mezcla normal, add, multiply, screen, erase, lighten, darken, none. Consulta capacidades con UG.Capabilities.webgpu(), webgl2(), webgl(), canvas().

Escalado y móviles

scale.mode: 'fit' (encaja manteniendo proporción, con bandas), 'envelop' (cubre recortando), 'fill' (estira), 'resize' (el tamaño lógico sigue al contenedor) o 'none'. Con autoCenter se centra. game.scale.toggleFullscreen() alterna pantalla completa.

  • Punteros unificados (ratón, táctil y lápiz) con multitáctil; MG.isTouch en los minijuegos muestra controles virtuales.
  • touch-action: none y sin menú contextual en el canvas; la entrada no captura teclas mientras escribes en un <input>.
  • El audio se desbloquea con el primer gesto (política de los navegadores móviles) y los efectos lanzados antes se descartan en lugar de acumularse.
  • La resolución se limita con maxResolution para no renderizar a 3× en teléfonos de gama baja.

Escenas

Una escena es un objeto (o clase) con key y métodos opcionales init(data), preload(), create(data), update(tiempo, delta). Dentro tienes: this.add, this.make, this.load, this.textures, this.anims, this.tweens, this.time, this.input, this.physics, this.cameras, this.sound, this.scene, this.events, this.rng, this.world (raíz) y this.hud (capa de interfaz que no se mueve con la cámara).

const Menu = { key: 'Menu', create() { this.add.button(400, 300, { text: 'Jugar', onClick: () => this.scene.start('Juego', { nivel: 1 }) }); } };
const Juego = {
  key: 'Juego',
  init(datos) { this.nivel = datos.nivel; },
  create() {
    this.add.hud.text(16, 16, 'Nivel ' + this.nivel);          // HUD: fijo en pantalla
    this.events.once('shutdown', () => { /* limpieza propia */ });
  }
};
new UG.Game({ scenes: [Menu, Juego] });

Gestión: this.scene.start(clave, datos), restart(datos), launch (en paralelo), run, pause/resume, sleep/wake, stop, switch, transition, bringToTop/sendToBack, isActive/isPaused/isSleeping. Las operaciones se aplican al final del frame para que nunca se rompa el bucle actual. Eventos de escena: preupdate, update, postupdate, pause, resume, sleep, wake, shutdown.

Fábricas this.add.*: sprite, image, animatedSprite, text, bitmapText, graphics, rectangle, roundRectangle, circle, ellipse, triangle, polygon, star, line, container, group, tileSprite / tilingSprite, nineSlice, mesh, rope, renderTexture, particles, particleContainer, zone, tilemap, tween, timeline, button, panel, progressBar, joystick, virtualButton, existing. this.make.* crea sin añadir (acepta un objeto de configuración).

Objetos de juego

Todo lo visible hereda de Container: posición, escala, rotación (rotation en radianes o angle en grados), sesgo, pivote, alpha, tint, blendMode, visible, depth/zIndex, scrollFactor y datos propios (setData/getData). Los métodos set* se encadenan.

const nave = this.add.sprite(200, 300, 'nave')
  .setOrigin(0.5, 0.8).setScale(2).setTint(0x74c0fc).setDepth(10)
  .setInteractive({ cursor: 'pointer', draggable: true });
nave.on('pointertap', () => nave.setFlipX(!nave.flipX));   // el volteo refleja dentro de su marco (como Phaser)

const grupo = this.add.container(400, 300);                     // transforma, filtra o enmascara varios a la vez
grupo.add(nave); grupo.setMask(new UG.Rectangle(-100, -100, 200, 200)); // un Rectangle = recorte rápido (scissor)
grupo.filters = [new UG.GlowFilter({ color: 0x9dfcff })];
grupo.cacheAsTexture = true; grupo.cacheResolution = 2;         // contenido estático: 1 textura, 1 draw call

Máscaras: obj.mask = otroObjeto (alfa del objeto máscara), obj.maskInvert = true, o un UG.Rectangle / setClip(x, y, w, h) para recortes rectangulares con scissor.

Graphics (vectorial)

Dibujo vectorial con API inmediata al estilo Phaser y de caminos al estilo Canvas. La teselación es propia: uniones miter/round/bevel sin triángulos solapados (las líneas semitransparentes no se «repintan»), trazos cerrados sin huecos en la unión, extremos butt/round/square, polígonos cóncavos con agujeros (earcut) y rellenos convexos en tira (sin grietas con MSAA).

const g = this.add.graphics();
g.fillGradientStyle(0x2b1055, 0x2b1055, 0xff8a5b, 0xffc371, 1).fillRect(0, 0, 800, 600);   // degradado por esquinas
g.lineStyle(6, 0xffffff, 0.5).strokeRoundedRect(40, 40, 300, 160, 24);                       // alfa sin solapes
g.fillStyle(0xffd43b).fillStar(600, 150, 5, 60, 26).lineStyle(4, 0xe67700).strokeStar(600, 150, 5, 60, 26);
g.beginPath().moveTo(100, 400).bezierCurveTo(200, 300, 300, 500, 400, 400).lineTo(400, 480).closePath().fillPath().strokePath();
g.fillStyle({ gradient: { type: 'radial', x: 600, y: 420, r: 80, stops: [[0, 0xffffff], [1, 0x7048e8, 0]] } }).fillCircle(600, 420, 80);

Métodos: fillStyle, lineStyle, fillGradientStyle, fillRect, fillRoundedRect, fillCircle, fillEllipse, fillTriangle, fillPoints, fillStar, strokeRect, strokeRoundedRect, strokeCircle, strokeEllipse, strokeTriangle, strokePoints, strokeStar, lineBetween, beginPath, moveTo, lineTo, arc, arcTo, quadraticCurveTo, bezierCurveTo, closePath, fillPath, strokePath, rect, roundRect, circle, ellipse, poly, star, regularPoly, cut (agujeros), clear, generateTexture. Texto

Text rasteriza con Canvas 2D (fuentes del sistema o web, relleno sólido o degradado, trazo, sombra, alineación, ajuste de línea, espaciado, fondo). Su canvas reserva capacidad en pasos de 32 px, así que un marcador que cambia de «9» a «10» reutiliza la misma textura de GPU. BitmapText usa una fuente en atlas (BMFont o generada) y no sube nada a la GPU al cambiar: es la opción para cientos de textos que cambian cada frame.

const titulo = this.add.text(400, 80, 'UltraGame', {
  fontFamily: 'system-ui', fontSize: 64, fontWeight: 900,
  fill: [0xfff3bf, 0xff6ad5], stroke: 0x2b1055, strokeThickness: 8,
  dropShadow: { offsetX: 0, offsetY: 4, blur: 8, color: '#000', alpha: 0.5 }
}).setOrigin(0.5);
titulo.text = 'Nuevo texto';                                   // se vuelve a dibujar solo si cambia
this.add.bitmapText(20, 20, 'mi-fuente', 'PUNTOS 0');          // this.load.bitmapFont('mi-fuente', 'f.png', 'f.fnt')
El texto de usuarios (nombres, chat) debe pasar por UG.Security.sanitizeText(texto, maxLargo): elimina caracteres de control y de reordenación bidi que se usan para suplantar nombres.

Carga de recursos

this.load.* en preload() (o this.load.start() manual). Usa fetch con cancelación y tiempo límite (60 s), valida URLs, limita tamaños y puede verificar la integridad con SRI.

preload() {
  this.load.setPath('assets/');
  this.load.image('fondo', 'fondo.png');
  this.load.spritesheet('heroe', 'heroe.png', { frameWidth: 32, frameHeight: 32 });
  this.load.atlas('ui', 'ui.png', 'ui.json');                        // formato TexturePacker (hash o array, trim, rotated)
  this.load.audio('salto', ['salto.ogg', 'salto.mp3']);
  this.load.json('datos', 'datos.json', { integrity: 'sha256-…' }); // falla si el hash no coincide
  this.load.tilemapTiledJSON('nivel1', 'nivel1.tmj');                // tilesets externos (.tsj/.tsx) e imágenes se cargan solos
  this.load.tilemapTMX('nivel2', 'nivel2.tmx');
  this.load.bitmapFont('pixel', 'pixel.png', 'pixel.fnt');
  this.load.font('Pixelify', 'pixelify.woff2');
  this.load.sfx('moneda', { preset: 'coin', seed: 3 });              // sonido sintetizado: sin archivos
  this.load.on('progress', (p) => console.log(Math.round(p * 100) + '%'));
}

Texturas por código: this.textures.generate(clave, w, h, (ctx, w, h) => { … }, { frameWidth, frameHeight, scaleMode, resolution }) — con frameWidth se registra como spritesheet. También addCanvas, createCanvas (canvas editable con refresh()), addSpriteSheet, fromDisplayObject.

Física Arcade

Cuerpos AABB y círculos con gravedad, rebote, fricción de arrastre (plataformas móviles), masas, empuje, velocidad máxima, amortiguación, colisión continua contra tiles (sin atravesar paredes), plataformas de un sentido, spatial hash para miles de cuerpos y paso fijo determinista.

// config: physics: { arcade: { gravity: { y: 900 }, debug: false } }
const jugador = this.physics.add.sprite(100, 100, 'heroe');
jugador.body.setSize(12, 20).setOffset(2, 4).setBounce(0.1).setMaxVelocity(300, 900);
const balas = this.physics.add.group({ maxSize: 40, defaultKey: 'bala', allowGravity: false });
const muros = this.physics.add.staticGroup();

this.physics.add.collider(jugador, capaSuelo);                           // contra una capa de Tiled
this.physics.add.collider(enemigos, capaSuelo, null, (e, tile) => e.tipo !== 'fantasma'); // processCallback
this.physics.add.overlap(balas, enemigos, (b, e) => { balas.killAndHide(b); e.destroy(); });
const impacto = this.physics.raycast(capaSuelo, x0, y0, x1, y1);          // DDA: { x, y, tileX, tileY, distance }
this.physics.world.wrap(asteroides, 32);                                  // envolver al lado opuesto

Cuerpo: setVelocity(X/Y), setAcceleration, setDrag, setDamping, setBounce, setFriction, setMass, setImmovable, setPushable, setAllowGravity, setGravity, setCollideWorldBounds, setCircle, setSize, setOffset, reset, stop; estado: blocked, touching, onFloor(), onWall(), onCeiling(), speed, angle. Mundo: setBounds, setBoundsCollision, setGravity, setFPS, pause/resume, overlapRect, overlapCirc, closest, furthest, moveTo, accelerateTo, velocityFromAngle, wrap. Tiles: setCollision, setCollisionBetween, setCollisionByProperty, setCollisionByExclusion, setOneWayCollision.

Tiled

Compatible con los formatos del editor Tiled: TMJ/JSON y TMX, tilesets embebidos o externos (TSJ/TSX), capas en CSV, base64, base64+zlib y base64+gzip (descompresor propio), mapas infinitos por bloques, grupos con desplazamiento/opacidad acumulados, propiedades tipadas (sin prototype pollution), objetos (rectángulos, puntos, elipses, polígonos, tiles), tiles animados, volteos H/V/diagonal, tileoffset, capas de imagen y orientaciones ortogonal, isométrica, staggered y hexagonal.

preload() { this.load.tilemapTiledJSON('nivel', 'mapas/nivel.tmj'); }
create() {
  const mapa = this.add.tilemap('nivel');           // también acepta el objeto JSON directamente
  mapa.createLayer('Fondo');
  const suelo = mapa.createLayer('Suelo', 0, 0);     // (nombre, x, y) o (nombre, contenedor, x, y)
  suelo.setCollisionByProperty({ collides: true });
  mapa.createLayer('Plataformas').setOneWayCollision(true);
  const monedas = mapa.createFromObjects('Objetos', { type: 'coin', key: 'moneda' });
  const inicio = mapa.findObject('Objetos', (o) => o.name === 'jugador');
  this.cameras.main.setBounds(0, 0, mapa.widthInPixels, mapa.heightInPixels);
  suelo.cacheAsTexture = true;                       // capas estáticas grandes: 1 textura (invalidada por putTileAt)
}

Capa: getTileAt, getTileAtWorldXY, putTileAt, removeTileAt, fill, replaceByIndex, forEachTile, filterTiles, findTile, getTilesWithin(WorldXY), worldToTileXY, tileToWorldXY (también en isométrico). Límites anti-DoS: mapas de más de Security.maxMapTiles tiles o datos comprimidos que se expanden por encima del límite se rechazan.

Ejemplo completo: Pixel Knight carga assets/level1.tmj con tileset externo y capa en base64+zlib (se puede abrir en Tiled).

Opciones: zonas de emisión (emitZone: { source: rect|círculo|elipse, type: 'random'|'edge' }), zonas de muerte, límites con rebote, rampas de color, rotación, estiramiento por velocidad, onEmit/onDeath. Con UG.Wasm.init() y emitter.useWasm(true) la integración corre en WebAssembly SIMD sobre memoria compartida con JS (sin copias): unas 4 veces más rápido que JS con 200 000 partículas en esta máquina (8,6 ms → 2,0 ms). Efectos (35)

Cada efecto es un filtro con su shader GLSL (WebGL/WebGL2) y WGSL (WebGPU); en Canvas 2D se usa el equivalente CSS cuando existe. Se aplican a un objeto (obj.filters = [...]) o a una cámara (cam.setFilters([...])), se encadenan y sus parámetros se animan con tweens. Las imágenes de abajo están generadas por el propio motor (examples/effects.html?tools=1); ábrelas en la galería interactiva para mover los parámetros en vivo.

Crear un efecto propio

class Ondas extends UG.Filter {
  constructor() { super(); this.fuerza = 4; }
  get fuerza() { return this.uniforms[0]; } set fuerza(v) { this.uniforms[0] = v; }
}
Ondas.key = 'ondas';   // único
// helpers: sampleTex(uv), texel(), pixelPos(coord), frameSize(), luma(rgb), rand(v2); tiempo = uGlobal.x / u.glob.x
Ondas.glsl = 'vec4 filterMain(vec2 uv, vec2 coord){ vec2 d = vec2(sin(coord.y * 40.0 + uGlobal.x * 4.0), 0.0) * texel() * uP[0].x; return sampleTex(uv + d); }';
Ondas.wgsl = 'fn filterMain(uv: vec2f, coord: vec2f) -> vec4f { let d = vec2f(sin(coord.y * 40.0 + u.glob.x * 4.0), 0.0) * texel() * u.p[0].x; return sampleTex(uv + d); }';
this.cameras.main.setFilters([new Ondas()]);

3D: primeros pasos

El 3D de UltraGame vive dentro de una vista 3D (View3D): un objeto 2D más de la escena que dibuja su mundo 3D en una textura. Eso significa que el HUD, los botones, los textos, las cámaras 2D y los 35 efectos funcionan encima del 3D sin nada especial, y que un juego puede mezclar escenas 2D y 3D libremente.

  • Backends: WebGPU, WebGL2 y WebGL (con la misma imagen en los tres). El renderizador Canvas 2D no tiene 3D: la vista muestra un aviso.
  • Iluminación PBR metal/rugosidad (como el Principled BSDF de Blender), sombras del sol con filtrado suave, cielo procedural, niebla, tonemapping ACES, sombreado cartoon con contorno, instancias, animación por huesos y partículas en una sola llamada de dibujo.
  • Sin dependencias: glTF/GLB, OBJ, física, controles y exportación a GLB están en el mismo ultragame.js.
const Mundo = {
  key: 'Mundo',
  preload() { this.load.gltf('robot', 'modelos/robot.glb'); },     // exportado desde Blender
  create() {
    const v = this.add.view3d({ fov: 60, shadows: true });        // sin tamaño: ocupa toda la pantalla
    v.add.sunlight({ shadowSize: 40 });                             // sol con sombras + luz de cielo/suelo
    v.add.box(30, 1, 30, { color: 0x6a8a5a }).position.y = -0.5;    // suelo
    const cubo = v.add.box(1, 1, 1, { color: 0x4c6ef5, metalness: 0.3, roughness: 0.4 });
    cubo.position.set(-2, 1, 0);
    const robot = v.add.model('robot');                             // instancia del glTF
    robot.play('Walk');                                             // animación del archivo
    v.orbitControls({ target: { x: 0, y: 1, z: 0 }, distance: 8 }); // ratón/táctil para mirar
    v.on('update3d', (dt) => { cubo.rotation.y += dt; });
    this.add.hud.text(20, 20, 'HUD 2D encima del 3D', { fontSize: 24, fill: 0xffffff });
  }
};
new UG.Game({ width: 1280, height: 720, renderer: 'auto', scenes: [Mundo] });
Coordenadas: metros, Y hacia arriba, rotaciones en radianes. La cámara es v.camera (PerspectiveCamera); v.scene3d es la raíz del mundo. v.screenToRay(x, y), v.pick(x, y) y v.worldToScreen(punto) conectan el 2D y el 3D (clics sobre objetos, barras de vida flotantes…).

Modelos: Blender, glTF/GLB y OBJ

El formato recomendado es GLB (glTF 2.0 binario): un solo archivo con mallas, materiales, texturas, esqueletos y animaciones.

Exportar desde Blender

  1. Modela en metros con Z arriba en Blender (el exportador lo convierte a Y arriba) y aplica la escala (Ctrl+A › Escala).
  2. Usa materiales Principled BSDF: color base, metálico, rugosidad, normal y emisión se traducen directamente.
  3. Animaciones: cada Action se exporta como un clip con su nombre (Idle, Walk, Run…). Para personajes, un único esqueleto (Armature) con pesos.
  4. Archivo › Exportar › glTF 2.0 con formato glTF Binary (.glb), «Aplicar modificadores» activado y, si hay animaciones, «Exportar animaciones».
  5. Nombra los nodos que el juego deba encontrar (por ejemplo wheel_FL para las ruedas de un coche o muzzle para la boca de un arma): modelo.getObjectByName('muzzle').
preload() {
  this.load.gltf('heroe', 'modelos/heroe.glb');           // también this.load.glb(...)
  this.load.obj('casa', 'modelos/casa.obj', 'modelos/casa.mtl');
}
create() {
  const v = this.add.view3d();
  const h = v.add.model('heroe', { cloneMaterials: true }); // materiales propios para teñirlo sin afectar a otras copias
  h.play('Run', { fade: 0.2 });                             // loop: 'repeat' | 'once' | 'pingpong', speed, weight
  const m = this.cache.models.get('heroe');
  console.log(m.clipNames);                                 // ['Idle', 'Walk', 'Run', ...]
}

Extensiones glTF admitidas: KHR_materials_unlit, KHR_texture_transform, KHR_materials_emissive_strength, KHR_mesh_quantization, KHR_lights_punctual, EXT_texture_webp. Draco y meshopt no (el cargador lo indica con un error claro): exporta sin compresión de mallas.

Seguridad de los archivos: el cargador valida todo antes de usarlo: cabecera y bloques GLB, límites de cada accessor y bufferView, índices fuera de rango, ciclos o nodos con dos padres, profundidad máxima, valores NaN, tipos de data: URI y URLs externas. Un GLB malicioso o corrupto produce un error, nunca un cuelgue ni acceso fuera de memoria.

Animación 3D

Cada instancia de un modelo tiene su propio mixer (AnimationMixer3D) y el atajo modelo.play(nombre, opciones). Las transiciones se hacen con fundido (fade); con exclusive: false se mezclan capas (por ejemplo «Disparar» encima de «Andar»).

robot.mixer.on('finished', (accion) => { if (accion === golpe) robot.play('Idle', { fade: 0.2 }); });
robot.mixer.on('loop', (accion) => { /* cada vuelta de un clip en bucle */ });
// clips hechos a mano: claves [tiempo, ...valores]; rotationX/Y/Z en radianes (se interpolan bien aunque den vueltas)
const girar = UG.AnimationClip3D.fromKeys('Girar', { puerta: { rotationY: [[0, 0], [1, Math.PI / 2]], position: [[0, 0, 0, 0], [1, 0, 0.1, 0]] } });

Física 3D

Física determinista a 60 pasos por segundo pensada para juegos: colisionadores estáticos (cajas, esferas, mallas exactas con rejilla espacial), cuerpos dinámicos, personajes (cápsula con escalones, rampas, salto con margen y empuje), vehículos (suspensión por rayos, derrape, choques), zonas (triggers), rayos y línea de visión.

Consejos

  • Agrupa las imágenes en atlas: el lote instanciado admite varias texturas por draw call, pero menos cambios siempre es mejor.
  • Fondos, decorados y capas de tiles que no cambian: cacheAsTexture = true (y cacheResolution = zoom de la cámara si la usas ampliada).
  • Miles de elementos simples (lluvia, estrellas, balas visuales): ParticleContainer o un emisor con WASM.
  • Muchos textos que cambian cada frame: BitmapText (sin subidas a GPU).
  • Reutiliza objetos con Group (get/killAndHide) en vez de crear y destruir en cada disparo.
  • Los filtros cuestan pasadas a pantalla completa: aplícalos a la cámara una vez en lugar de a cien sprites.

Memoria y fugas

Todo recurso con memoria nativa se libera de forma explícita y comprobable: destroy() en objetos (recursivo en contenedores), texturas (destroy(true) libera la fuente y sus texturas de GPU en todos los renderizadores), escenas (al pararlas se destruyen tweens, temporizadores, cuerpos, colisionadores, cámaras, sonidos y listeners), y game.destroy() (incluye loseContext() en WebGL y device.destroy() en WebGPU). El grupo de destinos de render recicla texturas temporales y libera las que no se usan en 600 frames.

console.table(UG.Debug.live);          // objetos vivos por tipo: DisplayObject, TextureSource, GPUTexture, Tween, PhysicsBody…
const antes = UG.Debug.snapshot();
this.scene.restart();                  // …juega un rato…
console.log(UG.Debug.diff(antes, UG.Debug.snapshot()));   // lo que no volvió a su valor

La batería de pruebas incluye pruebas de fugas por backend (crear y destruir juegos, escenas, texturas y filtros una y otra vez y comprobar que los contadores vuelven a la base), y los ocho minijuegos se han reiniciado repetidamente con contadores idénticos. En 3D también se cuentan Node3D, Geometry3D, GPUBuffer3D, GPUTexture3D, GPUTarget3D, View3D, PhysicsWorld3D, Model3D y AnimationMixer3D; la prueba de humo 3D juega los ocho juegos en los tres backends y exige que un ciclo GameOver → Play → GameOver deje todos los contadores igual.

Seguridad y web3

UltraGame reduce la superficie de ataque del lado del motor, pero ningún código de cliente es seguro por sí solo: en un juego web3 el cliente siempre puede ser modificado. Lo que sigue es lo que hace el motor y cómo usarlo bien.

Lo que hace el motor

  • Sin ejecución dinámica: el bundle no usa eval, new Function, innerHTML ni document.write (lo verifica el script de build y las pruebas), así que funciona con una CSP estricta.
  • Carga validada: Security.isSafeURL bloquea javascript:, vbscript:, data: no-imagen y variantes ofuscadas; Security.allowedOrigins limita los dominios; tamaños máximos por archivo, tiempo límite y cancelación.
  • Integridad: { integrity: 'sha256-…' } en cualquier this.load.* comprueba el hash (SHA-256 propio, igual al de crypto).
  • Datos no confiables: safeMerge y el parser de Tiled ignoran __proto__, constructor y prototype; propiedades en objetos sin prototipo.
  • Anti-DoS: límites de tiles por mapa, de expansión en zlib/gzip (bombas zip), de tamaño de textura, de longitud de texto y de partículas.
  • Texto de usuario: sanitizeText elimina controles y marcas bidi usadas para suplantar nombres.
  • Azar: Security.secureRandom() (criptográfico) para lo que deba ser impredecible; UG.RNG (xoshiro128**) con semilla para lo que deba ser reproducible y verificable.

Recomendaciones para juegos web3

  • Nunca pongas claves privadas, frases semilla ni secretos de API en el juego. Firma con la billetera del usuario (su extensión o app), jamás desde el código del juego.
  • Lo que tiene valor (recompensas, NFTs, marcadores con premio) se decide en el servidor o en el contrato, no en el cliente.
  • Partidas verificables: usa una semilla que el servidor conozca, graba la entrada con UG.InputLog y el paso fijo (fps.fixedStep), y compara UG.Debug.hashState(estado) al final; el servidor puede re-simular la física y la lógica en Node con el mismo bundle.
  • Sirve el juego con una CSP como default-src 'self'; script-src 'self'; img-src 'self' data: blob:; connect-src 'self' https://tu-api y con SRI en las etiquetas <script>.
  • Pide al usuario confirmar cada transacción fuera del bucle de juego, con importes claros.

UltraGame Studio

  • El servidor local del Studio solo escucha en 127.0.0.1, rechaza cabeceras Host ajenas (DNS rebinding) y usa un token aleatorio por sesión que se cambia por una cookie HttpOnly; SameSite=Strict; la API exige además una cabecera propia y Origin del propio servidor en las escrituras (CSRF).
  • Las rutas de archivos están confinadas a la carpeta de proyectos, con lista blanca de extensiones, límites de tamaño, escritura atómica, copia .bak y papelera recuperable. Los archivos subidos se sirven con CSP sandbox y como descarga (un SVG con scripts no se ejecuta).
  • El editor usa una CSP estricta y nunca inserta HTML: los nombres de objetos, recursos o proyectos maliciosos se muestran como texto.
  • «Jugar» ejecuta el juego en un iframe sandbox sin allow-same-origin: los scripts del juego no pueden leer la sesión del editor ni tocar tus archivos.
  • Los proyectos importados (.ugs.json) se validan campo a campo con el esquema: tipos desconocidos, rutas con .., claves __proto__, ciclos de padres y valores fuera de rango se descartan.

Depuración y herramientas

  • stats: true (o ?stats=1 en los minijuegos): FPS, ms por frame, draw calls, quads, texturas y objetos culled.
  • physics: { arcade: { debug: true } }: cuerpos, velocidades y colisiones dibujados.
  • game.snapshot() → PNG; new UG.Recorder(game).start({ fps: 15, scale: 0.5 }) → GIF (codificador propio con paleta por median cut).
  • UG.Debug.inspect(objeto) (árbol), UG.Debug.live, snapshot/diff, hashState.
  • game.loop.stop() + game.loop.step(16): avanzar frame a frame desde la consola o en pruebas.

Minijuegos

Ocho juegos completos, cada uno probando el motor desde un ángulo distinto. Todos tienen menú, récord, pausa, silencio, pantalla completa y controles táctiles.

Limitaciones conocidas

  • C++: el núcleo acelerado no está compilado desde C++ (no había compilador disponible); es un módulo WebAssembly SIMD escrito a mano (tools/wasm/, 535 bytes) que comparte memoria con JS sin copias. Hoy acelera la integración de partículas; la física y el render siguen en JS optimizado.
  • Minificación: el bundle se distribuye sin minificar (≈1,1 MB con el 3D; ≈300 KB con gzip). Puedes pasarlo por cualquier minificador estándar.
  • Canvas 2D: los efectos sin equivalente CSS se omiten en ese backend; es el respaldo para navegadores sin GPU, no el modo recomendado.
  • Comparativas: no se han medido PixiJS ni Phaser en este equipo; las cifras publicadas son solo de UltraGame. Para comparar, ejecuta escenas equivalentes de cada motor en el mismo navegador y máquina.
  • Seguridad: el motor aplica defensas razonables, pero ninguna biblioteca puede garantizar la ausencia total de vulnerabilidades ni proteger valor que dependa del cliente (ver Seguridad y web3).
  • Tipos TypeScript: dist/ultragame.d.ts está escrito a mano y se comprueba contra las exportaciones reales del motor, pero no se ha compilado con tsc en este entorno.
  • Física 2D: es Arcade (AABB/círculos). No incluye cuerpos rígidos con rotación ni uniones; para eso integra una biblioteca dedicada.
  • Física 3D: pensada para juegos (personajes, vehículos, esferas y cajas alineadas, colisión exacta contra mallas estáticas). Los cuerpos dinámicos no rotan por choques (salvo el rodar visual de las esferas) y no hay uniones ni telas.
  • glTF: sin compresión Draco/meshopt ni texturas KTX2; exporta desde Blender sin compresión de mallas. Las morph targets (formas clave / shape keys de Blender) no están soportadas: se usa la forma base y se avisa en la consola.
  • 3D en Canvas: el renderizador Canvas 2D no dibuja 3D (la vista 3D muestra un aviso); hace falta WebGL o WebGPU.
  • Studio: es una aplicación web local que se abre en una ventana de Edge/Chrome (no se ha empaquetado con Electron para no descargar dependencias). El HTML exportado como carpeta necesita un servidor web o un hosting; la exportación «HTML único» funciona sin servidor.
